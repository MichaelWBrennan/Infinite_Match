# Canonical client and sync contract

**Decision (2026-10-11):** the **Phaser web client** is the one canonical game. Every other client is a *consumer* that must match it, and none may fork its rules.

## What is canonical

| Layer | Files | Rule |
| --- | --- | --- |
| Rules (source of truth) | `src/services/levels/*.js` (`match-core`, `special-rules`, `shield-rules`, `objective-rules`, `generator`, `level-service`) | Pure, deterministic, integer RNG. Only change rules here. |
| Browser artifact | `public/js/procedural-levels.js` | Generated from the rules by `scripts/build-level-client.js`. Never hand-edit. |
| Golden vectors | `fixtures/golden/rules-v5.json` | Generated by `npm run vectors:build` from the rules. The language-neutral acceptance test for any other engine. |
| Client shell | `index.html`, `script.js` (DOM menus), `phaser3-game.js` (board), `public/js/*` | The canonical UI. |

## Commands

- `npm run build` regenerates the browser bundle (`scripts/build-level-client.js`).
- `npm run vectors:build` regenerates the golden fixture.
- `npm run check:sync` verifies that the committed bundle and fixture match the rules, and that the browser bundle reproduces every golden hash, RNG stream and level exactly (`src/__tests__/canonical-sync.test.ts`). It also runs as part of `npm test`.

Workflow after changing any rule: `npm run build && npm run vectors:build && npm run check:sync`. Commit all three outputs with the rule change. A rule change that alters the golden output is a new rules version or a deliberate, reviewed change to frozen behavior. Frozen paid definitions (v2–v4) must not change.

## Adding another client (for example Unity)

1. Port the rules, not the UI. Mirror `hashSeed`, `nextRandom` (32-bit integer arithmetic), and all weight and score arithmetic as IEEE-754 doubles in the same operation order.
2. Note that `hashSeed` iterates UTF-16 code units. A port must do the same, which the astral-character vector checks.
3. Load `fixtures/golden/rules-v5.json` in that engine's test suite and assert every hash, RNG output, level, and first move. A client is in sync only when that suite passes.
4. Report the client's rules version to the server and reuse the same `rulesVersion` values.

## Known limits

- Static Vercel deploys have no API. Until `/api/*` is routed to the Node server, a signed-in or account-dependent feature can look successful with empty data. Guest play generates levels locally from the bundle, so it does not depend on the API.

- The golden vectors cover one opening move per level, not full games, and not the location-to-context mapping (`location-context.js`). Extend them before claiming full parity.
- Passing the vectors proves rule agreement, not the look, layout, audio, or accessibility of a client.
- The Unity WebGL binaries and the Unity editor are not available in this repository's sandbox, so no Unity build has been tested against these vectors.
