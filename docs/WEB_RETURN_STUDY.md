# Voluntary web return study (D1/D7 activity signal)

**Off by default. No cohort has been measured here.** This is an optional, signed-in, web-only study of whether someone opens the game again on the next and seventh **UTC** days after joining. It does not measure guest play, first-play enjoyment, all sessions, app crashes, paid completions, or genuine human engagement. Do not call it a retention improvement or use it alone to tune paid difficulty.

## Consent and player experience

The web client's Explore menu contains **Help improve the game (optional)**. It never displays a forced prompt. A signed-in player may choose **I agree to join**, see their own participation state, and explicitly **Stop and delete my study days** with a second confirmation. Guests are never enrolled. Joining records that UTC day as day 0. Opening the signed-in web app after a successful account sync checks for consent and records at most one visit per UTC day; calling `/visit` before opt-in creates nothing. Joining again does not reset a cohort; withdrawing removes the entire keyed record, including its days, and rejoining after withdrawal starts a new cohort. Withdrawal works even if new enrollment has been paused. This study is **separate from ads consent** (`/api/consent`), account progress, achievements and payouts.

The study file contains only a secret-keyed HMAC pseudonym derived from the session's account ID, an enrollment UTC date and a set of visited UTC dates. It never stores account ID, email, IP, location, device, raw seed, board, purchase, hint or transcript. Pseudonymous day histories are still sensitive: keep the key out of source control, protect the file/backups and avoid shipping raw rows to analytics vendors. The app's ordinary authentication/access logs remain separate and may contain their usual security fields; this change does not claim to erase those.

## Enable and operate safely

1. Have an operator review the study wording/consent, age suitability, local data policy and hosting topology. Set a stable, secret `RETENTION_STUDY_KEY` of at least 32 characters and `RETENTION_STUDY_ENABLED=1` **only on a single server instance with a private durable local volume**. No key or disabled flag means no enrollment or visits. The optional `RETENTION_STUDY_FILE` defaults to `var/studies/retention.json` (ignored by Git). New files use mode 0600 where supported; writes replace the complete file atomically in one process. This is **not multi-replica-safe** or a backup/transaction solution. Do not enable it for a multi-server deployment until a shared transactional store and cross-replica withdrawal are implemented.
2. Keep the key stable for the study period. Losing/rotating it while data remains means existing participants cannot locate or withdraw their records; pause enrollment, restore the key for deletions, or stop all processes and securely delete the whole file and copies before rotating. Do not silently reassign pseudonyms. Pausing enrollment (`RETENTION_STUDY_ENABLED=0`) **does not** block status or withdrawal while the key remains available.
3. Records expire 35 UTC days after enrollment; expired records are pruned on any study status, join, visit, withdrawal, or admin report request. Consent therefore expires rather than silently persisting indefinitely. In a completely idle deployment, run an authenticated admin report or stop the service and securely delete the file/backups according to the retention policy; do not assume expiration while no process executes. To honour an erasure request, use the player's signed-in Delete control/`DELETE /api/retention-study/me`, and remove any operational backups according to policy.
4. The admin-only `GET /api/admin/retention-study` requires the existing `ADMIN_API_TOKEN` and `ADMIN_IDS` headers. It shows aggregate cohorts enrolled from today minus 28 UTC days through today. A D1 denominator consists only of people whose join day is at least one UTC day old; D7 requires seven days. A return is a web app open **exactly** on the first/seventh UTC day after joining, not a 24-hour or 7-day rolling window. Each reported cohort and each overall D1/D7 metric is suppressed until it has ≥20 eligible consented accounts. The 20 threshold is disclosure suppression, **not statistical power**. Reports never expose keyed pseudonyms or per-person dates. The report is `no-store`.

Example operator check (do not put a real token in a shell history or committed file): use the same protected admin client already used for other admin routes to fetch `/api/admin/retention-study` and inspect `d1`, `d7`, `cohorts`, `suppressedCohorts` and `basis`.

## Biases and remaining release gates

Only successfully authenticated **web account syncs** count as visits. Guests, accounts that never opted in, failed/offline syncs, network-disabled players, native/Unity sessions and players who withdraw are excluded. Multiple devices on one account count once per UTC day. Day-boundary travel and local-midnight expectations differ from this deliberately UTC definition. Withdrawal removes a person from denominator as well as numerator; self-selection and opt-out can bias rates. A client can request `/visit` while signed in without actually playing; it is not replay-verified engagement. Cohorts have different follow-up eligibility and reports censor young cohorts rather than calling them non-returners. Backups and app-wide security logs have their own retention controls.

The existing [offline observed first-play study](WEB_FIRST_PLAY_STUDY.md) must still be conducted with real people. Crash-free ≥1,000 consented sessions, fairness, input accessibility, actual completion, review of false replay rejections and controlled assignment remain **open**. A separate [offline session-stability kit](WEB_SESSION_STABILITY.md) can review submitted consented sessions, but no real sessions have been collected or automatically tracked here. No generated target or active paid definition is changed by this instrument. Do not launch team prizes, use D1/D7 as an A/B causal result, or claim a quality gate passed until those independent guardrails are genuinely observed.
